DNM MES 4.10.3 — 설치 및 사용방법
적용 대상: 4.10.1 또는 4.10.2 프로그램 / SQL28까지 적용한 기존 Supabase 프로젝트

■ 이번에 해결한 내용
1. 삭제한 수주가 「민수 LOT · Routing → 수주 / Shop Order」에 남는 문제 수정.
   이미 선택한 수주가 삭제되면 선택을 해제하며, 삭제 수주에 새 LOT 생성을 차단합니다.
   취소한 LOT의 이력은 상태를 「취소·이전 개정」 또는 「전체」로 선택하면 확인할 수 있습니다.
2. 관리자 전용 「수주관리 → 민수 자료 전환」 메뉴 추가.
   업로드 원문을 확인하여 실제 수주·LOT·작업지시로 전환하고 작업실적을 등록합니다.
3. 문제 자료 확인·보완, 사유를 남긴 제외, 재검토, 중복 전환 방지 기능 추가.
4. 기존 수주 상세 버튼 중복 수정, 500 LOT 분할, 수주/LOT 삭제와 작업일보 수정 기능 유지.

■ 설치 — 1번 SQL 적용 후 2번 프로그램을 복사하세요

1. Supabase SQL 적용
   현재 쓰는 Supabase 프로젝트의 SQL Editor를 엽니다.
   이 압축의 database 폴더 안 「29_upgrade_v4_10_3.sql」을 메모장으로 엽니다.
   SQL 내용을 전부 복사하여 SQL Editor의 새 쿼리에 붙여 넣고 Run을 누릅니다.
   별도 제공한 DNM_MES_v4.10.3_SQL29.sql도 같은 내용입니다. 둘 중 하나만 사용하세요.
   SQL28까지 성공한 프로젝트가 대상입니다. 과거 설치 SQL 전체를 다시 실행하지 마세요.
   이번 SQL은 전환용 함수와 삭제 수주 차단만 추가합니다.
   설치 자체로 기존 수주·작업일보·연차·직원·원문 자료를 삭제하거나 다시 만들지 않습니다.

2. 프로그램 복사
   먼저 ZIP을 PC의 새 폴더에 풉니다.
   GitHub Desktop에서 현재 DNM 저장소를 선택합니다.
   Repository → Show in Explorer를 누릅니다.
   탐색기에 기존 public 폴더와 package.json 파일이 보이는지 확인합니다.
   이번 압축에서 나온 「public 폴더」와 「package.json 파일」 두 항목을 복사하여
   위 탐색기 창의 빈 곳에 붙여 넣습니다. 같은 폴더는 병합, 같은 파일은 덮어씁니다.
   기존 public 폴더를 삭제하지 마세요. public 안에 public을 넣지 마세요.
   이 압축에 config.js는 없습니다. PC의 현재 public/config.js가 그대로 사용됩니다.
   database 폴더의 SQL은 1번에서 실행하는 파일이며 public 폴더에 넣지 않습니다.

3. 배포 확인
   GitHub Desktop → Commit → Push origin.
   Netlify에서 배포가 Published가 된 뒤 MES 로그아웃 → Ctrl+F5 → 관리자 로그인.
   브라우저 탭과 화면 버전 4.10.3을 확인합니다.
   Netlify 환경변수 변경이나 dnm-accounts 재배포는 필요하지 않습니다.

■ 이미 업로드한 자료를 실제 작업지시로 전환하는 순서

1. 관리자 로그인 → 수주관리 → 「민수 자료 전환」.
2. 「업로드했던 JSON 선택」에서 기존 파일을 선택합니다.
   DNM_민수부싱_2026_재공확인대기_PRIVATE.dnm.json
   이 파일 선택은 조회·대조용이며 같은 자료를 다시 등록하지 않습니다.
   파일이 없어도 DB 원문은 보이지만, 이전 형식의 LOT 대조와 원문 공정 불러오기는
   기존 JSON을 선택하는 것이 좋습니다.
3. 품번 / TYPE으로 범위를 좁히고 실제 현재 재공인 LOT만 선택합니다.
   같은 품번·TYPE끼리 선택합니다. 기본 100개이며 「한 번에 선택할 LOT 수」에서
   최대 500개까지 지정할 수 있습니다. 자료가 많으면 100개씩 확인하며 진행하세요.
4. 수량·상태가 불분명한 행은 「확인·보완」에서 확인값과 사유를 저장합니다.
   원본 수량·품번 등을 덮어쓰지 않고 전환용 확인값을 따로 저장합니다.
   동일 LOT 원문이 여러 건이면 사용할 원문 한 건을 먼저 확인합니다.
   「원문 미등록」이면 초기구축·운영 → 첨부자료 일괄등록에서 실제 등록부터 완료합니다.
5. 「선택 자료 수주·작업지시 전환」을 누릅니다.
   - 연결할 기존 수주를 선택하거나 「새 민수 수주 생성」을 선택합니다.
   - 새 수주는 고객명·품명·수주 전체 수량을 입력합니다.
   - 각 LOT의 수량과 현재 상태(미착수/작업 중)를 확인합니다.
   - 여러 행의 빈 수량·상태는 확인한 기본값으로 한 번에 채울 수 있습니다.
     이미 입력된 값은 바꾸지 않습니다. LOT별 예외 수량은 각 행에서 수정합니다.
   - LOT 합계는 기존 수주의 미배정 잔량을 넘을 수 없습니다.
     새 수주 수량도 전환 LOT 합계 이상이어야 합니다.
   - Shop Order와 Heat Code를 확인합니다. 미기재로 진행할 때는 확인란에 체크하고
     정식 고객 제출 문서를 발행하기 전에 민수 LOT → 공정·배정 →
     「S/O·Heat 보완」에서 실제 확인값과 사유를 저장하세요. 관리자만 가능합니다.
6. 공정 초안을 확인합니다.
   - JSON에 있는 TYPE별 원문 공정 또는 검토완료 제품 공정을 불러올 수 있습니다.
   - 공정 순서·명칭·처리구분·검사코드·순서 무관 여부를 담당자가 확인합니다.
   - 설비·작업자는 지금 배정하거나 실제 작업일보를 등록할 때 선택할 수 있습니다.
   - 원문 공정 초안 자체가 검토·승인된 작업지시를 의미하지는 않습니다.
7. 「작업지시를 배포」 체크와 전환 사유·검토 확인 후 저장합니다.
   완료 화면에서 성공 LOT와 문제 행을 따로 확인합니다.
8. 「연결 수주 보기」, 「민수 LOT 보기」, 「작업지시 보기」에서 확인합니다.
   실제 설비·작업자를 선택하여 작업시작/종료 또는 수기 작업일보를 등록합니다.
   작업자 화면에서 안 보이면 조회범위와 본인 작업자 계정 연결도 확인하세요.

■ 문제 자료 처리
- 수량·품명·현재 상태 등이 미확인인 행은 사유를 표시하고 작업지시로 만들지 않습니다.
- 「문제가 있는 행은 제외하고 가능한 행만 전환」 체크 시 정상 행만 전환합니다.
  체크를 해제하면 문제 행이 하나라도 있을 때 전체 요청을 저장하지 않습니다.
- 현물 확인이 어려운 자료: 선택 → 「선택 자료 제외」 → 제외 사유 입력.
  원문은 보존되며 처리 상태 「제외」에서 조회할 수 있습니다.
- 다시 사용할 자료: 선택 → 「선택 자료 재검토」 → 보완 후 전환.
- 이미 전환한 원문은 다시 선택해도 같은 운영 LOT를 중복 생성하지 않습니다.
- 전환 LOT를 적법하게 삭제·취소한 뒤 재작성하려면 원문을 재검토로 돌리세요.
  기존 취소 LOT와 원문 전환 이력은 보존됩니다.
- 연결 오류로 결과가 불확실하면 「같은 요청 다시 확인」을 사용합니다.
  동일 요청번호로 결과를 확인하므로 중복 생성하지 않습니다.

■ 확인할 점
제공된 2026년 재공확인대기 원문은 1,863건입니다.
이는 투입일이 2026년이고 납품완료일이 비어 있는 후보이며,
모두 현재 작업 중이라고 확정된 목록은 아닙니다.
원본에 없는 LOT 수량·Shop Order·Heat Code·과거 실적은 임의로 만들지 않았습니다.
전환 시 공정 누적수량은 0에서 시작합니다. 기존에 진행된 작업은 확인된 사실만
작업일보로 별도 등록하세요. 「순서 무관」 공정만 앞 공정 완료 전 등록할 수 있습니다.
원본 LOT 번호는 유지하며 내부 Routing 관리번호는 yymm-일련번호로 별도 부여됩니다.

기존 연차 테이블·사원번호 연결·환경설정·계정 서버 파일은 보존합니다.
PRIVATE JSON/엑셀/DB 백업은 GitHub나 public 폴더에 넣지 마세요.
이번 작업에서 운영 Supabase 자료를 대신 전환하거나 Netlify에 배포하지는 않았습니다.
