DNM MES 4.10.2 — 화면 오류 수정 / 업로드 자료 조회 보완
적용 대상: 현재 4.10.1 프로그램을 사용하는 DNM MES

먼저 확인하세요
이 압축은 프로그램 화면 수정본입니다. SQL을 실행하지 않습니다.
기존 Supabase 데이터·연차/사원번호 연계·로그인 계정·연결 설정은 변경하지 않습니다.
운영 사이트에 대신 배포한 상태는 아니며, 아래 순서로 적용해야 합니다.

A. 프로그램 적용 — public 폴더와 package.json 두 항목만 복사
1. 이 압축파일을 PC의 새 폴더에 풉니다.
2. GitHub Desktop에서 DNM 저장소를 선택합니다.
   Repository → Show in Explorer를 누릅니다.
3. 열린 탐색기에서 기존 public 폴더와 package.json이 보이는지 확인합니다.
4. 이번 압축에서 나온 public 폴더와 package.json을 함께 선택하여
   3번 탐색기 창의 빈 곳에 붙여넣습니다. 같은 파일은 덮어씁니다.
   public 폴더 안으로 들어가서 붙여넣는 것이 아닙니다.
   기존 public 폴더를 지우거나 새 폴더로 통째로 교체하지 마세요.
   이번 압축에 config.js는 없으므로 기존 public/config.js를 그대로 보존합니다.
5. GitHub Desktop에서 Commit → Push origin을 실행합니다.
6. Netlify 배포가 Published가 된 뒤 MES에서 로그아웃 → Ctrl+F5 → 다시 로그인합니다.
7. 브라우저 탭과 화면 버전이 4.10.2인지 확인합니다.

추가 SQL / dnm-accounts 재배포 / Netlify 환경변수 수정은 필요하지 않습니다.
이전 SQL을 다시 실행하거나 데이터베이스를 초기화하지 마세요.

B. 이미 업로드한 민수 부싱 자료 찾기
1. 관리자 로그인 → 초기구축·운영을 펼칩니다.
2. 「업로드 자료 · 과거 Routing」을 누릅니다.
3. 「업로드한 JSON 파일로 등록 여부 확인」에서 기존에 올린
   DNM_민수부싱_2026_재공확인대기_PRIVATE.dnm.json을 선택합니다.
4. 「선택 파일 · DB 등록 대조」 목록과 위쪽 건수를 확인합니다.
   - 파일 원문: 선택 파일의 참조자료 건수. 해당 제공 파일은 1,863건입니다.
   - DB에 원문 있음: 같은 코드 또는 LOT가 DB에서 조회된 건수입니다.
   - 기존 동일 LOT 보존: 예전에 저장한 원문이 있어 새로 추가하지 않은 건수입니다.
   - DB 원문 미확인: 이 계정으로 조회한 DB 원문에서 찾지 못한 건수입니다.
   - 동일 LOT 원문 여러 건: 원문을 비교하여 확인할 대상입니다.
5. 행 오른쪽의 「파일·DB 비교」와 「DB 원문」으로 실제 저장 내용을 확인합니다.
   비교표의 「선택 파일」과 「DB 원문」은 별도 열입니다.

3번의 파일 선택은 조회만 합니다. 다시 업로드하거나 저장하지 않습니다.
화면을 새로 열어 선택 파일 정보가 없어졌다면 같은 JSON을 다시 선택하면 됩니다.

C. 등록 화면과 조회 화면의 차이
- 「첨부자료 일괄등록」: 파일 선택 → 검토 확인 → 「선택 자료 일괄등록」까지
  실행해야 실제 DB 등록이 진행됩니다. 파일 선택만으로 등록되지는 않습니다.
- 파일을 선택한 등록 화면에 새로 추가한 「등록 자료 확인」 버튼을 누르면
  해당 파일과 DB를 대조하는 조회 화면으로 바로 이동합니다.
- 「새로 등록된 민수 부싱」 필터는 새 자료 형식만 표시합니다.
  예전 형식의 LOT는 「DB 원문 전체」 또는 위 파일 대조에서 확인합니다.

D. 이 JSON으로 등록되는 자료의 범위
이 파일은 수주·작업지시가 아닌 XLSM 원문 참조자료입니다.
수주관리 / 민수 LOT / 작업일보 / 생산진척에 작업실적으로 자동 표시되지 않습니다.
2026년 투입·납품완료일 미기재 1,863건을 확인대기로 추출한 자료입니다.
실제 현재 작업 중임을 확정한 목록은 아닙니다.
원본에 LOT 수량, S/O, Heat Code, 실제 공정실적이 없어 이를 임의로 만들지 않았습니다.
실제 운영 작업지시로 전환하려면 LOT별 수량과 현재 상태, 연결할 수주 등 확인이 필요합니다.

E. 이번 수정
- 수주 상세의 수정·삭제 버튼이 자동 새로고침마다 화면 상단에 누적되는 오류 수정.
- 버튼을 해당 수주 상세 안에 한 번만 표시하여 수정·삭제 동작과 연결.
- 오래 걸린 이전 조회가 새 수주/목록/다른 메뉴를 덮어쓰지 않도록 수정.
- 원문 파일의 LOT를 DB와 대조하여 기존 보존/미확인/여러 원문을 구분.
- 파일 선택을 DB 등록 완료로 잘못 표시하지 않음.
- 기존 500 LOT 생성, 수주 삭제/수정, 작업일보 수정/비고, 권한 기능 유지.

DB 원문 미확인이 남는 경우
등록 화면의 최종 처리 문구(신규 / 기존 보존 / 중단)와 대조 화면의 건수를 확인하세요.
미확인 표시는 데이터가 삭제되었다는 뜻이나 등록 실패 원인을 확정하는 문구가 아닙니다.
이 작업에서는 운영 Supabase에 접속하지 않아 실제 운영 등록 결과는 직접 확인하지 않았습니다.

PRIVATE JSON/엑셀/백업은 GitHub 또는 public 폴더에 넣지 마세요.
