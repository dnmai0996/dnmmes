=================================================

[이번 변경에서 하지 않는 것]
- Supabase 프로젝트/계정/API Key를 변경하지 않습니다.
- SQL을 새로 실행하지 않습니다. 기존 01/04/06/08도 재실행하지 않습니다.
- 기준정보 JSON을 다시 등록하지 않습니다.
- 기존 config.js, 수주, Routing, 작업일보, 사용자별 권한을 삭제/초기화하지 않습니다.
- 네이버웍스/복지챗봇/연차관리 저장소에 넣지 않습니다. 현재 DNM MES 저장소에만 적용합니다.

4. 변경된 사용방법
- 전체 펼치기/접기 버튼 없음. 각 그룹 제목을 눌러 하위 메뉴를 열고 닫습니다.
- 여러 그룹을 각각 열어둘 수 있습니다. 기존 그룹별 열림 상태를 가능한 범위에서 유지합니다.
- 다른 메뉴를 선택하면 해당 그룹을 펼치고 선택 항목이 왼쪽 메뉴 화면 안에 보이도록 맞춥니다.
- 선택 항목은 강조색 + '현재' 표시로 식별합니다.
- 오른쪽 상단 '현재 위치 > 그룹 > 화면명'으로 왼쪽 선택과 연결됨을 확인합니다.
- PC에서는 왼쪽 메뉴를 고정하고 메뉴 안에서 별도로 스크롤합니다.
- 휴대폰에서는 ☰ 메뉴 → 항목 선택 후 메뉴가 닫히고 해당 화면이 열립니다.
- 닫기(X), 바깥 영역 또는 Esc로 모바일 메뉴를 닫을 수 있습니다.
- 검색어 입력 후 갱신되는 기존 검색을 유지합니다. 그룹 개편이 DB 정렬/검색 규칙을 바꾸지 않습니다.

5. 작업지시 화면
- 생산관리의 새 '작업지시 · 배포현황'은 배포된 Routing의 공정별 조회 화면입니다.
- Routing/작업실적을 복사해서 새 DB에 만드는 것이 아닙니다.
- 진행/종료/전체, 품번·생산오더·Routing·공정·설비·작업자 검색 지원
- 품번 → 납기일 → Routing → 공정순서 정렬
- 초안/이전 개정/취소 Routing은 제외합니다.
- 실제 시작/부분종료/완료는 기존 터치/음성 작업입력 메뉴에서 수행합니다.
- 기존 'Routing' 조회권한을 그대로 사용합니다. 별도 권한을 강제로 부여하지 않습니다.

6. 설비·계측관리
- 기존 기준정보의 설비대장/계측기대장을 별도 그룹으로 옮겼습니다.
- 설비: 코드·명칭·분류·모델·규격·관리자·사용상태·원문 관리, 권한에 따른 등록/수정/Excel/CSV
- 계측기: 관리번호·분류·제조사·규격·도입일·차기교정 원문 관리, 권한에 따른 등록/수정/Excel/CSV
- 기존 입력자료가 그대로 보이며 별도의 재등록이 필요하지 않습니다.
- 예방보전 계획, 교정 자동알림, 정비비용 원장 등은 이번 추가 범위가 아닙니다.

7. 조회/등록 권한
- 관리자는 모든 메뉴, 직원은 기존에 허용된 메뉴만 표시됩니다.
- 대시보드 조회권한이 있으면 대시보드가 첫 화면입니다.
- 작업자에게 대시보드 권한이 없으면 기존처럼 '터치 작업입력'을 먼저 엽니다.
- 조회만 허용된 설비/계측기 사용자는 등록/수정 버튼이 표시되지 않습니다.
- 메뉴가 안 보이면 기존 사용자별 권한을 확인하세요. 관리자 권한을 무조건 부여하지 마세요.

8. 검수 범위
- 문법 32개/단위·정적 테스트 128개 통과
- 가상자료 Chromium DOM 화면검사 217개 통과, JavaScript 오류 없음
- PC 1440px, 짧은 높이 1280×600, 모바일 320/360/390/768px 확인
- 테스트용 메모리 세션과 가상 Supabase 응답을 사용했으며 실제 운영 DB·네트워크를 검증한 것은 아닙니다.
- 실제 휴대폰 마이크, 터치 장비, 운영로그인, 실데이터 저장은 배포 후 담당자가 확인하세요.

9. 배포 후 확인할 5가지
① 전체 펼치기/접기 버튼이 사라졌는지
② 대시보드와 수주/생산/구매/품질/설비·계측관리 그룹이 나누어졌는지
③ 설비·계측기 기존 자료가 그대로 보이는지
④ 아래쪽 메뉴 선택 후 강조/현재 위치/스크롤이 일치하는지
⑤ 작업자와 조회 전용 계정의 메뉴/등록/수정 권한이 유지되는지

이상 시 이전 GitHub 커밋으로 되돌리고 재배포하세요.
이번 업데이트는 DB를 변경하지 않으므로 메뉴 복구를 위해 SQL/자료를 초기화하지 않습니다.
