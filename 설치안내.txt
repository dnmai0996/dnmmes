(주)디엔엠 MES v4.8.1 — 환경설정·데이터베이스 변경 없는 배포본

1. 적용 방법
① 현재 GitHub Desktop 저장소 폴더를 별도로 백업합니다.
② 이 ZIP을 별도 폴더에 압축 해제합니다.
③ public, server, netlify, tools 폴더와 netlify.toml, package.json을 기존 저장소 루트에 병합 복사합니다. 기존 폴더 전체를 삭제하지 마세요.
   public 폴더를 기존 public 안에 넣지 말고 같은 위치에 합치세요.
④ public/config.js는 첨부 GitHub본과 바이트 단위로 동일합니다. 현재 PC의 설정을 이후에 바꾸었다면 config.js는 덮어쓰지 말고 현재 파일을 유지하세요.
⑤ GitHub Desktop에서 변경 내역 확인 → Commit → Push origin.
⑥ Netlify 자동 배포가 Published이면 기존 앱 주소를 열고 Ctrl+F5로 새로고침합니다.

SQL 실행, Supabase Edge Function 재배포, 환경변수 변경은 이번 배포에 포함되지 않습니다.
이 압축에는 SQL 설치파일과 Supabase 함수 배포파일을 넣지 않았습니다.
기존 Netlify 함수 코드는 변경 없이 포함했습니다. 기존 Netlify 빌드 설정을 그대로 사용합니다.
프로그램 시작 파일은 public/index.html입니다. 로컬 검토는 Node.js가 설치된 PC에서 npm run serve를 실행하고 http://127.0.0.1:4173을 엽니다. 실제 로그인에는 기존 서버 연결이 필요합니다.

2. 이번 변경
- 작업자 로그인 관리에서 미사용, 계정 미발급, 초기번호 만료, 첫 비밀번호 설정 대기, 정상 사용을 구분합니다.
- 미사용 작업자는 사용 전환 전 계정 발급·초기화 버튼을 표시하지 않습니다.
- 정상 로그인 인원 계산에 사용자 프로필 활성 상태도 반영합니다.
- 기존 소스와 같은 사업 데이터 구조, 인증 방식, 권한 규칙을 사용합니다.

3. 기존 기능 및 제한
- 관리자 이메일 로그인, 작업자 이름(ID) 로그인, 초기번호 1111, 첫 비밀번호 변경 기능은 기존 서버 기능을 이용합니다.
- 현재 운영 서버에 기존 SQL 18·20 및 dnm-accounts 기능이 설치되어 있어야 관련 기능을 사용할 수 있습니다. 설치 여부는 이번 작업에서 확인하지 못했습니다.
- 초기번호는 계정 발급 후 30분 동안 유효합니다. 만료 시 관리자가 재발급합니다.
- 첫 비밀번호는 기존 정책대로 문자와 숫자를 포함한 12자 이상입니다.
- 기존 사용 29명·미사용 18명을 자동 변경하지 않습니다. 전체 사용 전환·계정 일괄 생성·기존 권한 변경은 하지 않습니다.
- 사용 체크와 로그인 계정 발급은 별개입니다. 기존 작업자 목록에서 계정 미발급인 재직자는 관리자가 개별 발급합니다.
- 동명이인은 기존 서버가 부여한 이름-2 등의 ID를 사용합니다.
- 관리자가 화면에서 사용상태 변경·계정 발급·작업실적 저장을 실행하면 기존 방식대로 업무 데이터가 저장됩니다. 배포 자체는 DB를 변경하지 않습니다.

4. 검증 결과
- 변경 소스 포함 자동 테스트 252개 통과, JavaScript 56개 파일 문법검사 통과.
- 첨부 백업 17,390개 항목의 원본 프로그램 무결성 검사 통과.
- public/config.js, netlify.toml, server 및 netlify 함수 파일은 첨부본과 동일함을 검증.
- 실제 운영 Supabase 로그인·RLS 및 Netlify 배포 후 동작은 미검증.

5. 배포 후 확인
관리자 로그인 → 작업자 사용·로그인 관리 → 상태 확인.
이미 발급된 시험 작업자로 이름 로그인 및 첫 비밀번호 변경 확인.
미사용 작업자의 신규 로그인 및 기존 로그인 상태에서 업무 접근 차단 확인.
문제가 있으면 백업한 프로그램 파일을 다시 올리세요. 이번 배포로 DB를 변경하지 않으므로 DB 복원은 필요하지 않습니다.
