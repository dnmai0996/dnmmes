1. PC에서 PRIVATE ZIP의 압축을 풉니다.
2. MES 관리자 로그인 → 초기구축·운영 → 첨부자료 일괄등록.
3. DNM_v42_MasterData_PRIVATE.dnm.json을 선택합니다.
4. 종류별 건수와 원문 확인사항을 검토합니다.
5. 기존 수주를 보존하려면 수주 추가 체크를 하지 않습니다. 첨부 10개 수주를 넣을 때만 별도 체크합니다.
6. 백업·원문검토 확인을 체크 → 선택 자료 일괄등록.
7. 100행씩 처리합니다. 창을 닫거나 다른 메뉴로 이동하지 마세요.
8. 일부 통신 실패 시 완료된 묶음은 보존됩니다. 같은 파일로 다시 실행하면 동일코드는 건너뜁니다.
9. 이미 있는 동일코드는 덮어쓰지 않습니다. 다른 코드의 같은 직원/거래처명이 있으면 중복 생성하지 않고 경고합니다.
10. 과거 Routing이 필요한 경우 DNM_v42_RoutingHistory_PRIVATE.dnm.json을 같은 화면에서 별도 등록합니다.

[5] 원본 확인과 활성화
- 기준정보 검토·활성화 화면에서 종류별 검색 → 선택 → 검토완료 처리.
- 표시된 30행 선택 또는 '검색결과 미확인 200건 검토'로 묶어서 검토·활성화 가능합니다. 원본 미확인 상태로 일괄 승인하지 마세요.
- 공구/자재의 단위가 없으면 같은 단위의 행을 검색·선택하고 실제 단위를 입력합니다. 단가를 0원으로 채우지 않습니다.
- 13개 계측기 행 중 3개 '다수 보유' 묶음은 개별번호 확인 후 각각 등록해야 하며 일괄활성화되지 않습니다.
- 제품명 표기가 다른 경우 제품 화면에서 표시명을 확정합니다. 원문 변형/REV 후보는 남습니다.
- 별도 Excel 대장은 검토용입니다. Excel의 검토완료 표시는 DB에 자동으로 반영되지 않습니다.

[6] 작업자 로그인 및 권한
1. 기존 직원 Auth 계정이 있으면 그대로 사용합니다. 없으면 v4.3의 초기구축·운영 → 사용자 등록·초기화에서 작업자를 로그인 사용자로 등록합니다. (UPGRADE_v4_3_KO.txt 우선 참조)
2. 앱 사용자관리에서 활성 여부·표시이름·기본역할을 확인합니다. 일반 직원은 member, 조회 전용은 viewer, 관리자만 admin입니다.
3. 사용자별 권한 → 직원 선택 → 현장 작업자/생산관리/구매/품질/기준정보/조회전용 권한안 선택.
4. 각 메뉴의 조회·등록·수정 및 본인/담당 또는 전체 범위를 검토 후 사유를 입력하고 저장합니다.
5. 현장 작업자는 worklogs 조회/등록/수정, 본인/담당 범위가 기본입니다. 시작뿐 아니라 종료·수정하려면 수정권한도 필요합니다.
6. 대시보드는 주문·Routing 조회도, Routing 작성은 주문·템플릿 조회도 필요합니다.
7. 결재/전결은 메뉴권한과 별도로 결재자 체크·한도·기간을 확인합니다. 관리자 지정과 결재자 지정은 다릅니다.
8. 기본 viewer 계정에 등록·수정 권한을 부여하려면 먼저 member로 바꾸어야 합니다. admin은 전체 권한이므로 작업자에게 부여하지 마세요.

[7] 계정·설비·공정을 묶어서 연결
1. 초기구축·운영 → 계정·설비 일괄연결.
2. 작업자 계정 연결: 같은 표시이름은 후보만 보여줍니다. 계정이 본인인지 확인하고 행 체크 후 저장합니다.
3. 설비 담당관리자: 설비를 선택하여 Routing 권한이 있는 생산관리자를 지정합니다.
4. 설비·작업자·가능공정: 설비·작업자 선택 후 공정명을 체크하여 저장합니다.
5. 원문 작업자 파악현황의 66개 작업자 칸이 공란이므로 이 단계는 추정으로 자동 채우지 않습니다.
6. 같은 설비·작업자 연결을 다시 저장할 때는 선택 공정목록이 갱신되므로 필요한 공정을 모두 체크합니다.

[8] Routing Sheet 작성 및 배포
1. 기준정보 → 제품 Routing 또는 Routing 원문 후보에서 공정순서·검사코드·설비원문·REV를 검토합니다.
2. 충돌 품번은 원문 후보를 열어 '템플릿으로 검토' 후 적합한 공정안을 저장합니다.
3. 현장·생산 → 수주 → Routing 초안 → 담당관리자와 수주 선택 → 초안 생성.
4. 정확한 품번의 검토완료 템플릿만 적용합니다. 기존 DRAFT/RELEASED/DONE Routing이 있으면 보존합니다.
5. 원문 설비후보와 관리자가 확정한 설비·작업자·가능공정 연결이 한 가지로 일치하면 배정을 초안에 반영합니다. 후보가 없거나 여러 개면 공란입니다.
6. 주문별 LOT·재질·REV·수량·설비·작업자·담당관리자를 최종 확인한 뒤 배포합니다.
7. 제품 템플릿 변경이 이미 배포된 주문 경로와 과거 실적을 덮어쓰지 않습니다.
8. Routing 출력은 첨부 양식 구조를 유지합니다. 원본 도장/서명을 자동 전사하지 않습니다.

[9] 작업일보와 TV
- 작업자는 로그인하여 본인 배정작업만 조회합니다.
- 터치 작업입력과 음성 작업입력은 별도 메뉴입니다. 실제 시작·종료·완료 수량은 현장 확인 후 입력합니다.
- 작업일보 사전양식 메뉴에서 Routing/품번/공정/설비/작업자/지시수량을 채운 빈 실적양식을 출력할 수 있습니다.
- 출력은 작업실적 저장이 아닙니다. 과거 XLSM 2,875행으로 신규 작업일보를 만들지 않습니다.
- 대시보드는 지시/공정상태/처리수량을 보여줍니다. 수량 미확정은 확인대기로 남습니다.
- 부분종료와 공정완료를 구분하고, 모든 공정이 완료되어야 Routing 종료가 됩니다. 품질합격·출하는 별개입니다.

[10] 메뉴 사용
- 현장·생산 / 구매·품질 / 기준정보 / 초기구축·운영의 네 그룹.
- 제목을 누르면 접기/펼치기. 전체 펼치기는 본인 조회권한이 있는 메뉴만 표시합니다.
- 모바일은 왼쪽 상단 ☰ 메뉴로 선택합니다. 개인별 펼침상태가 브라우저에 보존됩니다.
- 권한은 메뉴 숨김뿐 아니라 SQL/RPC/RLS에서도 검사하도록 구현했습니다. 실제 Supabase 검수는 필수입니다.

[11] 반드시 시험할 8가지
- 무권한 사용자가 조회/등록/수정 API를 직접 호출해도 차단되는지
- 작업자 A가 B의 작업·기준정보를 볼 수 없는지
- 조회만 허용한 계정에 저장 버튼과 저장권한이 없는지
- 실제 관리자만 권한·일괄등록·활성화를 수행하는지
- 동일 초기자료를 다시 등록해도 중복/덮어쓰기가 없는지
- 수주→Routing초안→배정→배포→시작→부분종료→완료가 연결되는지
- 실제 휴대폰/터치PC/TV에서 저장·갱신·로그아웃이 정상인지
- 기존 사용자·기존 수주·기존 Routing·기존 실적이 보존되는지

[12] 확인한 것 / 아직 확인하지 못한 것
- 로컬 JavaScript 문법검사, 단위/정적검사, 실제자료 변환형식 검사, 모의API Chromium 화면검사 수행.
- 로컬 PostgreSQL이 없어 실제 SQL 실행·RLS·동시거래는 이 환경에서 수행하지 못했습니다.
- GitHub Actions 임시 PostgreSQL 통합시험 파일을 포함했습니다. 통과 후 시험 Supabase에서 재확인하세요.
- 실제 Netlify 배포, 실제 휴대폰 음성, 운영로그인/계정발급/데이터 등록은 하지 않았습니다.
- 브라우저 음성인식 유지. Ollama/사내 STT 연결은 이번 배포 범위가 아닙니다.
