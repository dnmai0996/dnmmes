# DNM v4 업무 사용순서

## 기본 사용
회사에서 발급한 기존 Supabase 이메일과 비밀번호로 로그인합니다. 로그인 문제는 ‘Supabase 연결 진단’으로 인증 서비스 도달 여부를 확인합니다. 연결 성공만으로 DB권한·업무 기능 성공까지 의미하지 않습니다.
페이지 제목 우측 ‘사용방법’은 현재 업무의 입력/처리순서를 안내합니다. 조회자는 일부 등록 버튼이 보이지 않습니다.

## 관리자 첫 설정
1. 사용자 관리에서 계정 활성/역할 확인.
2. 업무권한·전결에서 필요한 기능만 부여.
3. 작업자에 사번·성명·부서 등을 등록하고 실제 이메일 계정과 연결.
4. 설비에 담당 생산관리자 지정, 실물확인 후 사용활성.
5. 설비·작업자 연결에서 가능공정명 지정. Routing 공정명과 정확히 같아야 함.
6. 다른 직원 계정으로 본인 작업만 입력되는지 시험.

## 고객주문·Routing
1. 고객수주 신규 또는 자료 가져오기에서 등록.
2. 원본82열에서 생산오더·PO·계약품목·납기·고객정보 대조.
3. 수주 상세에서 Routing 신규 작성. 제품별 공정순서 추가/제외/이동.
4. 소재/가공/검사/외주/포장 유형 지정. 원본공정도를 그대로 정답으로 가정하지 않음.
5. 각 가공 단계의 설비와 작업자 배정. 관리자의 담당설비 및 가능공정 검사.
6. 배포 후 작업자 ‘나의 작업’에서 조회.
7. 실적 전까지 새 개정 가능. 실적 발생 후에는 기존 이력을 보존하고 변경을 차단.

## 작업자 실적
- 본인 배정된 대기공정 선택 → 시작 → 완료.
- 완료 시 총수량·불량수량 확인. 양품은 총수량−불량수량.
- 수량을 모르면 확인대기로 저장. 확정 전 완료공정/생산실적으로 잘못 집계하지 않음.
- 수기입력은 시작/종료 시각과 사유를 입력. 같은 시간의 중복작업 차단.
- 음성입력은 별도 동의 후 활성화. 인식문장을 먼저 확인·수정하고 수량을 대조한 뒤 저장.
- 작업일보의 시간은 일·시가 아닌 분 계산이며 7시간40분은 7.40시간과 다름.

## 긴급지시·대시보드
생산담당자가 납기/우선순위/사유를 변경합니다. 담당자가 긴급지시 확인을 남깁니다.
대시보드는 수주·설비·작업자별로 전환하고 대형화면 모드를 사용할 수 있습니다.
15초 갱신은 사용자 입력·팝업 작업 중에는 중단합니다. 마지막 갱신시각을 확인합니다.
공정별 수량을 합쳐 주문 완료수량으로 사용하지 않습니다.

## 구매
구매요청은 공급업체, 품목, 규격, 단위, 수량, 단가, 부가세와 결재자를 선택합니다.
결재선은 순서를 지정하고 필요한 후속 결재는 ‘필수’로 표시합니다.
현재 순번의 담당자만 승인/반려할 수 있습니다. 전결은 관리자에게 부여받은 한도·기한 내에서만 가능합니다.
승인 완료 후 발주번호 등록 → 부분 또는 전체입고 → 반품이 있으면 원입고를 지정해 반품등록.
전체 합격입고 완료 후 증빙번호/금액 대조 → 지급증빙 참조기록. 실제 송금은 하지 않습니다.

## 품질·출하
최종검사는 배포 Routing의 모든 공정 완료 후 기록합니다. 출하량은 최종 합격량을 넘을 수 없습니다.
고객반품은 출하된 범위에서 사유/NCR번호를 기록합니다. 재작업·재출하는 별도 담당자 검토 대상입니다.
품질문서 메뉴는 성적서 번호·문서구분·파일 참조경로를 관리합니다. 원본 파일 내용을 변환·서명하지 않습니다.
인쇄는 시스템 기록사본이며 공식 고객 제출 여부는 품질담당자가 확인합니다.

## Excel 가져오기
관리자 PC에서 XLSX 업로드를 권장합니다. 구형브라우저는 tools/xlsx_to_dnm_json.py로 값만변환 후 .dnm.json을 선택합니다.
고객명/검토사유/검토체크가 없으면 등록되지 않습니다. 차단오류는 원본을 수정하여 해결합니다. 기준정보는 정상행만 먼저 등록하는 제외 옵션을 명시적으로 선택할 수 있으며, 수주는 원본 오류를 먼저 수정해야 합니다.
응답이 끊겼을 때는 입력을 바꾸지 않고 ‘같은 요청 다시 확인’ 또는 등록목록을 확인합니다.
권한/검증 오류와 ‘등록됐을 수도 있는 통신 오류’는 다른 메시지로 안내합니다.

## 백업 및 오류 보고
관리자 백업에서 업무자료 JSON을 받습니다. 파일은 접근제한된 위치에 보관합니다.
에러 보고에는 메뉴, 작업, 시간, 에러문구, 가상 재현자료만 포함하고 비밀번호/JWT/비밀키를 공유하지 않습니다.
데이터 삭제나 Supabase 테이블 초기화로 오류를 해결하려고 하지 마십시오.
