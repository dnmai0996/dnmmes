# v4.1 제약·필수 검수

1. 실제 Supabase/PostgreSQL에서 06 SQL의 실행·권한·동시성을 이 환경에서 검증하지 못했습니다. CI와 시험 프로젝트 검수를 우선해야 합니다.
2. 브라우저 시험은 모의 API입니다. 계정/DB/실물장비 운영검수로 대체할 수 없습니다.
3. 브라우저 음성인식은 지원·마이크권한·네트워크에 따라 다르며 Chrome에서는 외부 음성서비스로 전송될 수 있습니다. 회사 승인 없이 민감정보 발화 금지. 로컬Ollama/STT는 미연결입니다.
4. 음성 인식 결과로 자동 저장하지 않습니다. 수량·작업·동작 확인 후 저장합니다. 모호한 한국어 수 표현 등을 임의 추정하지 않습니다.
5. 작업자/설비 각각 동시작업 1건 정책입니다. 복수설비 동시가공은 별도 정책·설계 대상입니다.
6. 공정처리량은 불량을 포함한 총처리량이며 납품합격량과 별개입니다. 현재 모든 공정 지시수량은 주문수량을 따릅니다. 불량으로 다음 공정 투입량을 줄이는 별도 WIP/재작업 라우팅은 이번 요청 범위 밖입니다.
7. 부가금액/단위는 원본 입력값 보존. 구매자재 마스터는 수량 원장이 아니라 기준정보이며 실제입고는 구매업무에서 처리합니다.
8. 한 주문의 실행 경로에 실적이 있으면 임의 신규 경로 생성/교체를 막습니다. 단순 품번매칭을 넘는 복수개정·분할LOT 병행 생산은 별도 설계 필요.
9. A4 Routing은 원본 항목/표구조 재현이며 스캔본 픽셀단위 복제는 아닙니다. 서명·검사도장은 공란입니다. 긴 공정설명·프린터여백에 따라 실제 출력 미리보기 확인 필요.
10. 초기 갱신15초, 센서실시간연결/OEE 아님. 기능별 조회 상한20,000건. 대량 장기자료는 향후 서버검색/기간조회 설계 필요.
11. 업무 JSON 내보내기는 전체 백업/자동복원기능이 아닙니다. Supabase Auth, 별도첨부파일,DB 복구절차 별도.
12. 원본 자료의 미확정값/중복코드/검토 안 된 템플릿은 자동 정정하지 않습니다. 현업 확인 후 활성화.
13. 테스트자료 자동삭제 기능은 이번 버전에 추가하지 않았습니다. 기존 실제자료 삭제/초기화 SQL을 실행하지 마십시오.
