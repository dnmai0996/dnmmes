# v4.2.1 추가 한계

이번 업데이트는 화면/조회 개편이며, 실제 Supabase 또는 Netlify 설치를 수행하지 않았습니다. 작업지시 조회는 Routing 조회권한을 사용합니다. 대시보드 없는 작업자는 본인 터치입력에서 시작합니다. 설비·계측기 그룹은 기존 대장 기능을 연결하며 예방보전·교정 자동알림 엔진을 새로 제공하지 않습니다.

---

# v4.2 한계와 운영 전 필수 조건

1. 실제 Supabase 프로젝트에 접근하지 않았고 SQL을 실제 PostgreSQL에서 실행하지 못했습니다. GitHub Actions의 임시DB 시험 및 시험 Supabase 검수를 통과해야 운영 가능 여부를 판단할 수 있습니다.
2. 모의 API 화면 점검은 실제 인증·RLS·트랜잭션·동시성 검증이 아닙니다. 실제 UI가 보인다는 이유로 운영 DB 적용을 생략하면 안 됩니다.
3. 기준정보에는 원본 공란·차이가 있습니다. 66설비 작업자 공란, 3개 계측기 개별번호 미확정, 8품번 공정후보 충돌, 원문 공구단위/단가 공란을 임의 채우지 않았습니다.
4. 현재 직원47명은 명부 당시 현재구역입니다. 현재 재직 및 권한을 확인해야 합니다. 계정·비밀번호 자동발급, 무인권한상승 없음.
5. Routing 템플릿은 제안/검토대기입니다. 공정유형·원문 번호·품번/REV·설비·작업자를 확인한 뒤 배포해야 합니다. 원문과 확인된 배정이 유일할 때만 초안 자동연결하며 복수 후보는 비웁니다.
6. 제품/거래처 명칭은 원문을 보존한 표시초안입니다. 문서 내 표기차이를 자동 확정한 것이 아닙니다.
7. 과거2875행은 참조 전용. 작업시각·수량·납품/품질승인·재고 이동 실적으로 생성하지 않습니다.
8. 현재 서비스는 하나의 회사 프로젝트 기준입니다. 여러 회사의 테넌트 분리 구현이 아닙니다. Supabase admin 계정은 전체권한이므로 일반직원에 부여하지 마세요.
9. 메뉴권한은 개별 페이지/작업 기준이며 일부 화면은 연계자료 조회권한이 함께 필요합니다. 직접 SQL/RPC 권한 변경은 앱의 역할 연결과 달라질 수 있어 사용자별 권한 메뉴를 사용하세요.
10. 초기등록은100행 묶음으로 각각 커밋됩니다. 전체파일 단일원자거래가 아닙니다. 중단시 일부등록 가능, 동일파일 재실행은 기존코드 건너뜀. 덮어쓰기/삭제/자동복구 버튼 없음.
11. 기존 자료와 다른 코드로 같은 품목이 이미 있으면 기존코드와 연결여부를 담당자가 확인해야 합니다. 제품코드가 다른 것을 이름만 보고 합치지 않습니다.
12. 앱 JSON 백업은 Auth 비밀번호와 Storage 첨부 실제파일 백업이 아닙니다. 전체복원 계획을 따로 유지해야 합니다.
13. 실제 휴대폰 음성/설비소음/산업용터치PC/프린터는 미검증. 브라우저 음성은 외부인식 서비스를 쓸 수 있으며 방산정보 정책을 확인해야 합니다. Ollama는 미연결입니다.
14. 네트워크 오류 시 승인/배포/실적 결과가 불명확하면 목록 재조회 후 재시도하세요. API키·토큰·비밀번호를 캡처에 포함하지 마세요.
15. Excel 검토대장은 자료 대조용입니다. 해당 파일을 편집해 업로드하여 DB 수정하는 기능은 이번 묶음파일 가져오기와 다릅니다.
