DNM CLOUD MES · 4.3.0

작업자 계정은 프로그램에서,
비밀번호는 본인이 설정

현재 v4.2.1 사용자용 안내입니다.

기존 config.js·기준정보·계정·업무자료를 유지합니다. 이번에는 서버 기능과 DB 확장이 필요하므로 화면파일만 교체하면 안 됩니다.

이번 버전의 핵심

직원은 Supabase에 접속하지 않습니다. 관리자가 DNM 앱에서 본인 이메일로 등록하고, 직원은 초기번호 1111로 접속하여 개인 비밀번호를 설정합니다. 인증·데이터는 기존 Supabase를 유지합니다.

1. 기존 파일·DB 백업

public/config.js와 기존 GitHub 커밋, 복구 가능한 Supabase DB/Auth 백업을 확보합니다. 앱 JSON 백업만으로 로그인 비밀번호까지 복구되지는 않습니다. 시험 브랜치와 별도 시험 프로젝트에서 검수합니다.

2. DB 확장

기존 v4.2 SQL 08까지 적용한 프로젝트에 database/10_upgrade_v4_3.sql을 적용합니다. database/11_verify_v4_3.sql로 조회 확인합니다. 01/02/04/06/08은 재실행하지 않습니다. tests/sql은 운영에서 실행하지 않습니다.

3. Netlify 환경변수 2개

DNM_SUPABASE_URL = 기존 config.js와 같은 프로젝트 URL

DNM_SUPABASE_SECRET_KEY = 같은 프로젝트의 Secret key(sb_secret_...) 또는 service_role

키는 Netlify Functions 환경변수로만 저장합니다. Functions scope(또는 All scopes)를 포함하고 배포 컨텍스트를 확인합니다. 공개용 키가 아니라 서버 비밀키입니다. config.js·GitHub·채팅에 넣지 마십시오.

4. 전체 패치 배포

public + server + netlify/functions + netlify.toml 등 패치 전체를 GitHub에 반영합니다. 기존 config.js를 지우지 않습니다. Publish=public, Functions=netlify/functions입니다. Netlify 배포 Published 이후 새로고침합니다. 환경변수 변경 후에는 새 배포가 필요합니다.

5. 관리자 계정 등록

관리자 로그인 → 초기구축·운영 → 사용자 등록·초기화 → 계정 서버 연결 확인 → 작업자의 로그인 사용자 체크 → 본인 이메일·재직 확인 → 계정 등록. 새 계정은 본인 작업 기본권한이며 기존 계정의 권한은 보존합니다.

6. 직원 첫 사용

관리자가 등록한 본인 이메일 + 1111 → 새 비밀번호 2회 입력 → 설정완료 → 이메일+새 비밀번호로 다시 로그인합니다. 초기번호는 30분, 설정화면은 최대 5분입니다. 변경 전 업무자료 접근을 차단합니다.

7. 비밀번호 분실·변경

관리자는 직원의 1111 초기화 버튼에서 관리자 자신의 비밀번호를 확인합니다. 직원은 로그인 후 상단 비밀번호 변경에서 현재 비밀번호 확인 후 변경할 수 있습니다. 사용 체크 해제는 접속 중지이며 과거 실적 삭제가 아닙니다.

8. 보안과 검수

1111은 공용번호라 이메일을 아는 다른 사람이 먼저 설정할 위험이 남습니다. 당사자가 접속할 때만 발급하십시오. 실제 Supabase·Netlify의 등록/초기화/권한/이전 세션 차단을 검수해야 합니다. 이 제작환경에서는 모의 API 시험만 수행했으며 실제 운영에는 접속하지 않았습니다.
