DNM MES v4.4 적용 안내 (현재 v4.3 사용자용)

이번 변경: 업무자료 전체 백업·시점 복원 / 진행률·대기 커서 / 짧은 화면 안내 / 관리자·현장 매뉴얼.

1. 기존 자료와 public/config.js를 별도 보관하세요.
   기존 업무백업이 실패하면 운영자료를 지우지 말고, 설치 담당자가 Supabase 플랫폼 백업/덤프를 먼저 확보하세요.
2. 시험 프로젝트에서 database/12_upgrade_v4_4.sql 적용과 GitHub 자동검사를 확인하세요.
   확인 후 기존 프로젝트에 같은 12번 SQL을 적용합니다. 이전 04·06·08·10은 재실행하지 않습니다.
3. 패치 폴더 전체를 기존 MES GitHub 저장소에 병합 → Commit → Push → Netlify 배포 완료 확인.
   public/config.js는 유지합니다. netlify/functions와 server 폴더도 포함해야 합니다.
   기존 v4.3 환경변수 2개는 그대로 사용합니다. 새 키를 만들 필요는 없습니다.

사용 위치: 초기구축·운영 → 백업 · 복원
사용 매뉴얼: 각 화면 ‘사용방법’ → 관리자 운영 매뉴얼 / 현장 사용자 매뉴얼

백업: 파일 비밀번호 입력 → 전체 업무자료 백업 → 내려받은 .dnmbak 파일 보관.
복원: 원하는 파일 검사 → 현재자료 안전백업 다운로드 → 안전파일 재선택 → 관리자 확인 → 복원.

주의: v4.4에서 만든 같은 프로젝트의 백업만 앱에서 복원합니다.
기존 JSON 내보내기 파일은 자동 복원하지 않습니다.
계정 비밀번호·현재 보안상태·변경이력은 유지합니다. 외부 문서파일과 프로그램은 별도입니다.
백업 이후 입력·수정한 업무자료는 복원 시 되돌아갑니다.
실제 운영자료에 앞서 시험자료로 백업·복원과 권한 차단을 확인하세요.
