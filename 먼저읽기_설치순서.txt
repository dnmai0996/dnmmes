디엔엠 MES v4.9.0 통합 수정본 — 설치 순서

이번 버전은 이전의 DB 변경 없는 v4.8.1과 다릅니다.
작업자 자동 로그인과 권한 관리를 위해 승인하신 SQL 및 로그인 함수 보완이 필요합니다.
프로그램만 먼저 덮어쓰지 말고 아래 순서대로 적용하십시오.
기존 Supabase 프로젝트 URL·공개키·Netlify 연결 설정은 그대로 사용합니다.

1. 현재 상태 보관
현재 MES에서 업무 백업을 내려받고 GitHub Desktop 저장소 폴더를 별도 복사합니다.
업무 백업에는 Supabase Auth 비밀번호·세션·로그인 제어정보가 포함되지 않으므로 인증 전체 복원용으로 간주하지 마세요.

2. 설치 전 조회(데이터 변경 없음)
Supabase의 기존 DNM 프로젝트 → SQL Editor → 새 쿼리.
installation/00_READ_ONLY_CHECK.sql 전체를 붙여넣어 실행합니다.
앞의 dnm_v42_setup, dnm_v42_set_access가 true여야 합니다.
구버전 로그인 함수가 false여도 통합 설치 SQL이 필요한 계정 기능을 추가합니다.
기본 업무 스키마가 없으면 설치 SQL이 오류로 중단하며 트랜잭션을 취소합니다.

3. 통합 SQL 한 번 적용
새 쿼리에서 installation/01_APPLY_WORKER_PURCHASE.sql 전체를 실행합니다.
이 파일만 실행하십시오. 이전 01~20번 SQL을 다시 실행하지 마십시오.
기존 사용자·제품·수주·Routing·실적은 삭제하지 않습니다.
최초 적용 시 작업자 명부를 모두 ‘사용’으로 전환합니다. 첨부 백업에서는 47명(기존 미사용 18명 포함)입니다.
현재 운영 DB에 추가된 작업자가 있으면 그 작업자도 최초 전환 대상입니다.
이후 미사용으로 전환한 작업자는 설치 SQL을 재실행해도 다시 사용으로 바뀌지 않습니다.
관리자에게 연결된 보호 계정은 일반 작업자 전환에서 제외됩니다.
기존 함수는 내부에 보존하고 로그인·결재 권한 검사를 덧붙입니다.
처리 오류가 나면 임의로 일부 줄만 실행하지 말고 오류 문구를 확인하십시오.

4. Supabase 로그인 함수 갱신
같은 프로젝트 → Edge Functions → dnm-accounts를 선택하여 코드 편집.
함수가 없다면 dnm-accounts 이름으로 새 함수를 만듭니다.
installation/02_DNM_ACCOUNTS_FUNCTION.txt의 전체 내용을 index.ts에 넣고 Deploy합니다.
이 함수의 Verify JWT 설정은 OFF로 둡니다. 최초 로그인 전 요청을 받아야 하기 때문입니다.
대신 함수 코드 안에서 관리자 토큰·권한과 초기번호를 검증합니다.
Supabase가 제공하는 서버 환경변수를 이용하므로 Netlify에 Secret key를 추가하지 않습니다.
허용 사이트는 현재 운영 주소 https://dnmmes.netlify.app 입니다.
공식 참고: https://supabase.com/docs/guides/functions/function-configuration
공식 참고: https://supabase.com/kb/troubleshooting/edge-function-401-error-response
CLI를 사용하는 경우에는 동봉한 supabase 폴더의 함수와 config.toml을 사용할 수 있습니다.

5. 프로그램 업데이트
GitHub Desktop → 현재 DNM 저장소 → Repository → Show in Explorer.
이 압축의 program 폴더 ‘안에 있는’ public/server/netlify/tools/netlify.toml/package.json을 저장소 루트에 병합 복사합니다.
program 폴더 자체를 저장소에 넣는 것이 아닙니다. public/public 중첩 경로를 만들지 마세요.
기존 폴더 전체를 삭제하지 마세요.
public/config.js는 첨부 GitHub본과 바이트 단위로 동일합니다. 이후 설정을 바꿨다면 PC의 현재 config.js를 유지하세요.
Commit → Push origin → Netlify Published 확인 → 앱에서 로그아웃 → Ctrl+F5 → 관리자 재로그인.
브라우저 탭·메뉴·대화상자의 주요 버전 표시는 4.9.0입니다.

6. 최초 자동 계정 연결
관리자 첫 로그인 때 사용 중인 작업자의 미발급 계정을 순차적으로 자동 생성·연결합니다.
완료될 때까지 창을 닫지 마세요. 기존 연결 계정의 비밀번호와 권한을 자동 초기화하지 않습니다.
초기구축·운영 → 작업자 사용·로그인 관리에서 전체 작업자와 로그인 ID를 확인합니다.
연결 미완료가 표시되면 오류를 확인한 뒤 ‘계정 연결 재시도’를 실행합니다.
Supabase에서 작업자 계정을 일일이 만들거나 수동 연결할 필요가 없습니다.
새 작업자 등록/사용 전환 후에도 자동 연결합니다.
작업자 이름(ID) + 1111 → 새 비밀번호 설정 → 이름(ID) + 새 비밀번호로 로그인합니다.
초기번호 1111은 최초 비밀번호 설정 전까지 유효하며, 설정 후에는 사용할 수 없습니다.
비밀번호 설정 화면 자체의 유효시간은 5분입니다. 만료되면 초기 로그인부터 다시 진행합니다.
새 비밀번호는 기존 정책대로 문자와 숫자를 포함한 12자 이상입니다.
동명이인은 목록에 표시된 이름-2 등을 사용합니다. 괄호가 포함된 기존 성명도 허용합니다.
미사용 전환 시 새 로그인과 기존 세션의 업무 접근이 차단되고 이력은 유지됩니다.

7. 작업자 권한 및 구매 결재자 지정
초기구축·운영 → 사용자별 권한·전결 → 작업자별 ‘조회·등록·수정·결재 지정’.
작업자 명부 전체가 보이며, 신규 자동계정 기본권한은 본인 작업일보 및 최소 조회권한입니다.
필요한 메뉴의 조회·등록·수정과 본인/전체 범위를 지정하고 변경 사유를 입력하여 저장합니다.
구매 결재를 맡길 사람은 ‘구매 결재자’를 체크합니다.
이때 일반사용자 역할과 구매 조회권한이 함께 선택됩니다. 신규 구매 조회는 본인/담당 범위가 기본입니다.
필요시 전결한도·기간을 별도로 지정합니다.
관리자 자신도 구매 결재자 목록에 나오려면 관리자 행의 ‘구매 결재자 지정/해제’를 사용합니다.
구매 → 구매의뢰서 작성 → 결재자 추가에는 현재 지정된 사용 가능 결재자만 표시합니다.
요청자 자신은 자기결재 방지를 위해 목록에서 제외합니다.
기존에 열어 둔 작성창은 닫고 다시 여세요. 상신/승인 시 서버가 현재 권한을 다시 확인합니다.
결재권 해제나 미사용 전환은 이미 보관된 결재 이력을 삭제하지 않습니다.

8. 구매 품명·규격 검색
구매의뢰서의 품명에 일부 문자 입력 → 포함하는 품목 후보 버튼 표시 → 품목 선택.
해당 품목에 연결된 규격 목록에서 선택하거나 규격을 직접 입력합니다.
품목이 없으면 새 품명과 규격을 그대로 입력할 수 있습니다.
품목 변경 시 이전 규격·단위·단가를 비워 다른 품목의 값이 남지 않도록 했습니다.
미사용·검토대기 자료는 ‘참고’로 표시하며 선택해도 기준정보를 활성화하지 않습니다.
미사용·검토대기 참고자료의 단가를 자동 확정하지 않습니다. 실제 구매 단가는 확인 후 입력하세요.
직접 입력한 품목은 해당 구매의뢰에 저장되며 자재 기준정보에 자동 신규 등록되지는 않습니다.
첨부 백업의 자재·공구 원본은 총 3,099행입니다. 동일 품목·규격은 검색에서 통합될 수 있습니다.

9. 설치 후 확인
installation/03_VERIFY_READ_ONLY.sql을 SQL Editor에서 실행합니다.
설치 상태가 true인지, 작업자 전체/사용/계정연결 수가 예상과 맞는지 확인합니다.
시험 작업자로 첫 로그인·비밀번호 변경·본인작업 조회를 확인합니다.
미사용 전환 후 접속 차단, 사용 재개 후 기존 비밀번호 유지 여부를 확인합니다.
구매 결재자 지정/해제 후 작성창 목록 변경, 품목 검색·규격 선택·직접입력을 확인합니다.

검증 범위와 제한
첨부 백업을 복제한 PGlite(PostgreSQL 호환) 환경에서 SQL 설치·재실행·계정 연결·세션 차단을 검증했습니다.
실제 Supabase Auth API의 계정 생성 및 비밀번호 변경, Edge 런타임 실행, 운영 Netlify 배포는 아직 직접 검증하지 않았습니다.
DOM 동작 시험은 통과했으나 실제 Chrome/모바일 브라우저의 시각적 배치는 이번 실행환경에서 검증하지 못했습니다.
이 파일을 제공하는 것만으로 운영 사이트가 변경되지는 않습니다. 위 3~5단계 적용이 필요합니다.
