디엔엠 MES 4.9.4 | 민수 작업지시와 공정별 순서 설정

1. 현재 운영 자료를 백업합니다.
   MES 관리자 로그인 → 초기구축·운영 → 백업·복원. 프로그램 ZIP은 PC에서 먼저 압축을 풉니다.

2. 기존 DNM Supabase 프로젝트에서 SQL을 실행합니다.
   이미 4.9.3의 24번 SQL을 적용했다면 이번에는 database/25_upgrade_v4_9_4.sql 한 개만 실행하세요.
   4.9.2의 23번 SQL까지만 적용한 경우에는 24번 → 25번 순으로 한 번씩 실행합니다.
   4.9.1에서 4.9 작업자·구매 SQL까지 적용한 경우에는 23번 → 24번 → 25번 순서입니다.
   SQL Editor → 새 쿼리 → 해당 SQL 파일 내용을 전체 복사·붙여넣기 → Run. 각 단계에 Success가 표시된 뒤 다음으로 진행합니다.
   25번 SQL은 업무 테이블을 초기화하지 않습니다. 기존 자료의 공정 순서는 기본 ‘순서 준수’로 처리됩니다.

3. 기존 GitHub Desktop 저장소에 파일을 합칩니다.
   GitHub Desktop에서 기존 dnmmes 저장소 선택 → Repository → Show in Explorer.
   원래 public 폴더와 netlify.toml이 보이는 창을 그대로 둡니다.
   다른 탐색기 창에서 ZIP을 푼 곳을 엽니다. 그 안에 있는 public, server, netlify, tools, database, supabase 폴더와
   netlify.toml, package.json 파일을 함께 선택해 복사하고 앞에서 연 dnmmes 창에 붙여넣습니다. 같은 이름의 파일은 ‘교체’를 선택합니다.
   붙여넣은 뒤 dnmmes → public → index.html이 보이면 맞습니다. 기존 public 폴더를 먼저 삭제하지 마세요.
   기존 PC의 public/config.js를 계속 사용합니다. 기존 Netlify 설정과 로그인 함수는 이번 변경을 위해 다시 설정할 필요가 없습니다.

4. 배포합니다.
   GitHub Desktop의 Summary에 ‘MES 4.9.4 민수 공정별 순서 설정’ 입력 → Commit → Push origin.
   Netlify에서 방금 변경한 배포가 Published인지 확인한 뒤 앱을 Ctrl+F5로 새로고침하고 로그인합니다. 탭과 로그인 버전은 4.9.4입니다.

5. 현장에서 확인합니다.
   • 민수: 고객 수주 → Routing 바로 작성 → 민수 일일 방식 선택. 선행 완료를 기다릴 필요가 없는 공정만 ‘순서 무관’을 체크합니다.
     사전 배정 방식은 배정 후 배포, 현장 설비 선택 방식은 저장과 동시에 작업지시가 발행됩니다.
     두 방식 모두 생산관리 → 작업지시 · 배포현황에서 발행한 지시를 볼 수 있습니다.
   • 이미 발행된 민수 지시: 수주관리 → Routing Sheet 관리 → 공정·배정 → 대상 공정의 ‘순서 설정’. 담당 생산관리자 또는 관리자가 설정합니다.
     작업·검사 이력이 생긴 해당 공정의 설정은 잠깁니다. 다른 미착수 공정은 개별 설정할 수 있습니다.
   • 작업자: 생산관리 → 터치 작업입력. 사전 배정은 본인 카드의 ‘작업 시작·재개’ 또는 ‘수기 작업일보’를 선택합니다.
     현장 설비 선택 방식은 ‘민수 현장 작업 시작’ 또는 ‘민수 현장 수기 작업일보’에서 공정과 실제 설비를 고릅니다.
   • 방산: 전 공정 순서 준수. 앞 공정이 끝나기 전에는 뒤 공정의 작업 시작과 수기 실적 등록이 차단됩니다.
   • 예: 010은 대기, 020은 순서 무관, 030은 순서 준수라면 020의 작업일보를 먼저 남길 수 있습니다.
     030은 010과 020이 모두 끝나야 시작합니다. 최종검사·출하 수량 기준은 기존과 같습니다.
   • 앱의 사용방법에서 「방산·민수 생산과 육안검사 안내 (PDF)」를 열 수 있습니다.
