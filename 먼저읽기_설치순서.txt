디엔엠 MES v4.9.3 | 기존 운영 사이트 업데이트

준비
현재 운영 중인 4.9.2를 기준으로 합니다. 관리자 계정에서 초기구축·운영 → 백업·복원으로 업무자료를 백업합니다.
다운로드한 프로그램 ZIP을 바탕화면 등에서 먼저 압축 해제합니다. 다음 절차는 파일을 삭제하지 않고 기존 저장소에 합치는 방법입니다.

1. Supabase에서 업무 기능을 추가합니다.
   기존 DNM Supabase 프로젝트를 엽니다. SQL Editor → 새 쿼리를 선택합니다.
   압축을 푼 곳의 database 폴더에서 24_upgrade_v4_9_3.sql을 메모장으로 엽니다.
   그 내용을 전체 복사해 새 쿼리에 붙여넣고 Run을 누릅니다. Success가 나오면 2번으로 갑니다.
   • 4.9.2 SQL(23) 확인 메시지가 뜨고 현재 4.9.1을 운영 중이면 기존 4.9 작업자·구매 SQL 설치 여부를 확인한 후,
     함께 넣은 23_upgrade_v4_9_2.sql을 먼저 실행하고 성공한 뒤 24번을 실행하세요.
   • 이미 4.9.3을 적용한 프로젝트에서는 23번을 다시 실행하지 마세요.
   • 오류가 표시되면 프로그램 복사 전에 SQL Editor의 오류 내용을 확인하세요.

2. PC에서 복사할 위치를 엽니다.
   GitHub Desktop → 현재 dnmmes 저장소 → Repository → Show in Explorer.
   원래 public 폴더와 netlify.toml이 보이는 이 창을 열어 둡니다. 여기가 붙여넣을 곳입니다.

3. 압축 안의 항목을 기존 저장소에 붙여넣습니다.
   다른 탐색기 창에서 압축을 푼 곳을 열어 public 폴더와 netlify.toml이 보이는 위치로 갑니다.
   그 안의 public, server, netlify, tools, database, supabase 폴더와 netlify.toml, package.json 파일을 선택해 복사합니다.
   2번에서 연 창의 빈 곳에 붙여넣고 ‘대상 폴더의 파일 교체’를 선택합니다.
   복사 후 경로 예: dnmmes → public → index.html. 원래 public 안에 public을 한 번 더 넣지 않습니다.
   원래 dnmmes 폴더를 통째로 지우지 마세요. 기존 public/config.js는 PC에 있는 파일을 사용합니다.

4. 운영 화면을 갱신합니다.
   GitHub Desktop → Changes → Summary에 ‘MES 4.9.3 민수 일일 생산’ 입력 → Commit → Push origin.
   Netlify에서 방금 푸시한 배포가 Published가 되면 MES를 새로 열고 Ctrl+F5 → 로그인합니다.
   브라우저 탭과 로그인 표시는 4.9.3입니다. 기존 4.9.2 로그인 함수는 이번 변경을 위해 재배포할 필요가 없습니다.

설치 후 첫 확인
• 관리자: 기준정보 → 설비 등록에서 기존 설비가 보이는지 확인합니다. 설비 신규 등록 시 ‘실제 업무 확인 완료 · 사용 중’을 체크합니다.
• 생산관리자: 고객 수주 → Routing 바로 작성에서 ‘생산 방식’과 민수 선택 시 ‘작업 예정일 / 이번 시트 계획수량’이 보이는지 확인합니다.
• 작업자: 생산관리 → 터치 작업입력 → 민수 현장 작업 시작. 사용 중인 연결 작업자 계정과 작업일보 등록·수정 권한이 필요합니다.
  선행 공정이 있으면 해당 공정이 완료된 다음에 후속 가공이 표시됩니다. 검사·자재입고 등 관리 공정은 담당 관리자가 처리합니다.
• 품질담당자: 품질관리 → 품질 · 출하 → 해당 수주의 검사 → ‘공정검사’와 ‘육안검사’를 고르고 해당 Routing 공정을 확인합니다.
• 「사용방법 → 방산·민수 생산과 육안검사 안내 (PDF)」에서 2쪽짜리 사용설명서를 열 수 있습니다. 파일은 public/manuals 안에도 있습니다.

기존 전량 시트는 방산 방식으로 이어집니다. 이미 전량 시트가 있는 수주에 민수 시트를 섞을 수 없습니다.
민수 시트는 초안·진행·완료 수량을 모두 계획에 포함합니다. 미착수 시트를 사유와 함께 취소하면 계획 가능 수량에 반영됩니다.
