디엔엠 MES 4.9.5 | 구매 품목별 비고, 발주 취소·수정·재발주

설치 순서
1. 현재 운영 중인 MES에서 관리자 로그인 → 초기구축·운영 → 백업·복원으로 업무자료를 백업합니다.
2. ZIP을 PC에 압축 해제합니다. 기존 DNM Supabase 프로젝트에서 SQL Editor → 새 쿼리를 엽니다.
   이미 4.9.4의 25번 SQL을 적용했다면 이번에는 database/26_upgrade_v4_9_5.sql 한 개만 실행하세요.
   파일을 메모장으로 열어 전체 선택 → 복사 → SQL Editor에 붙여넣기 → Run → Success 확인.
   이전 단계에서 바로 올라오는 경우, 4.9.3(24번 적용)은 25 → 26, 4.9.2(23번 적용)는 24 → 25 → 26 순으로 적용합니다.
   기존 4.9.1 작업자·구매 SQL을 설치한 상태에서 올라오는 경우 23 → 24 → 25 → 26 순서입니다.
   한 번에 하나씩 실행하고 각 단계의 Success를 확인하세요.
3. GitHub Desktop에서 기존 dnmmes 저장소 선택 → Repository → Show in Explorer.
   원래 public 폴더와 netlify.toml이 보이는 창이 프로그램 복사 대상입니다.
4. 압축을 푼 다른 창에서 public, server, netlify, tools, database, supabase 폴더와
   netlify.toml, package.json 파일을 선택해 3번 창의 빈 곳에 붙여넣고 ‘같은 이름의 파일 교체’를 누릅니다.
   복사 후 dnmmes → public → index.html이 보이면 맞습니다. 기존 public 폴더를 먼저 지우지 마세요.
   public/config.js는 PC에 있는 것을 사용합니다. 이 ZIP에는 덮어쓰기용 연결 설정이 없습니다.
5. GitHub Desktop → Summary에 ‘MES 4.9.5 구매 입고·발주 변경’ 입력 → Commit → Push origin.
   Netlify에서 방금 푸시한 배포가 Published가 되면 앱을 Ctrl+F5로 새로고침하고 로그인합니다.
   탭과 로그인 표시가 4.9.5인지 확인하세요. 기존 4.9.4 로그인용 Edge Function은 계속 사용합니다.

사용 방법
구매관리 → 발주 · 입고 · 반품 → 해당 발주의 ‘발주·입고 상세’를 엽니다.
• 비고만 저장: 품목별 입고현황의 잔량 오른쪽에 최대 500자 입력 → 같은 품목의 ‘비고 저장’.
  입고 등록 화면에서도 선택한 품목의 비고를 이번 입고수량과 함께 저장할 수 있습니다.
  별도 입고검사 메모는 개별 입고기록에 기록됩니다. 품목별 비고는 내부용이며 구매처용 출력 문서에 실리지 않습니다.
• 부분입고 후 변경: ‘수정 발주서 발행’ → 변경 후 총 발주수량 입력 → 변경 사유 입력 → ‘수정 발주서 발행’.
  예를 들어 면장갑 300개 중 200개를 합격 입고했다면, 더 받을 수 없을 때 200을 입력하고 50개를 더 받을 때 250을 입력합니다.
  수정 수량은 해당 품목 누적 합격입고(반품 차감) 이상, 의뢰 승인수량 이하입니다. ‘전 품목 잔량 취소 수량 채우기’로 남은 수량을 일괄 마감할 수 있습니다.
  수정 발주서는 기존 발주번호와 새 차수로 발행합니다. 이미 입고한 품목의 입고단가·수량·정산 기준과 최초 구매의뢰·결재 기록이 보존됩니다.
• 입고 전 취소: ‘발주 취소’ → 사유 입력 → ‘발주 취소 확정’. 입고·반품·지급 이력이 없는 건에 사용합니다.
  ‘재발주 대기’ 건의 상세 → ‘새 발주서 작성 (재발주)’ → 새 발주번호, 실제 구매처, 승인 범위 내 수량, 단가 확인 → ‘새 번호로 재발주’.
• 문서와 이력: 저장 후 발주·입고 상세에서 ‘발주서 PDF·인쇄’ 또는 ‘발주서 이미지 공유’를 선택합니다.
  ‘이전 발주서 및 변경 사유’를 펼치면 당시 수량·금액·구매처·처리자·사유를 볼 수 있습니다.
• 권한: 비고만 수정하거나 발주서를 변경하려면 해당 건에 대한 발주·입고·반품 수정 권한이 필요합니다.
  입고 등록 권한이 있는 담당자는 입고 시 비고를 함께 기록할 수 있습니다. 정산 대사·지급 완료 상태에서는 발주수량 변경이 제한됩니다.
