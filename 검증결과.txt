DNM MES 4.10.2 수정·검증 결과 / 2026-11-12

확인된 원인
1. 4.10.1 수주 상세 확장 코드가 document 전체의 첫 .actions를 선택하여
   실제 상세 영역이 아닌 페이지 제목 옆 도구 영역에 버튼을 추가함.
   15초 자동 새로고침마다 버튼이 누적되고, content 밖이어서 클릭 처리도 연결되지 않음.
2. 부싱 원문 가져오기에서 같은 LOT는 기존 원문을 보존하지만 조회 필터는
   source_family=DNM_BUSH_XLSM인 새 형식만 선택함.
   예전 원문에는 이 표시가 없을 수 있어 필터에 나타나지 않을 수 있음.
   실제 사용자의 DB에 해당 상황이 발생했는지는 직접 접속하여 확인하지 않음.

수정
- 수주 상세 필드와 동작을 하나의 화면 렌더링에서 구성. 전역 DOM 추가 삭제.
- 요청 순번, 현재 수주, 현재 메뉴, content 요소의 일치 여부를 확인하여 지연 응답 무시.
- DB에서 읽은 원문과 선택 JSON의 코드/원본 LOT를 대조하는 조회 기능.
- 신규 형식 표시가 없어도 기존 LOT를 조회. 미확인 파일 행은 미저장 상태로 분리 표시.
- 파일 값과 실제 DB 원문을 구분하며 기존 자료를 자동 변경하거나 생성하지 않음.
- 업로드 후 확인 버튼, 원문 조회 메뉴 명칭, 도움말 보완.

시험 결과
- Node.js 279개 통과 (기존 267개 + 원문 대조/권한 12개).
- 기존 화면 컨트롤러 DOM 39개 통과.
- 신규 DOM 회귀시험 28개 통과.
  실제 컨트롤러와 전역 heading/actions가 있는 화면 구조에서 40회 반복 갱신,
  민수↔방산, 상세↔목록, 다른 메뉴 이동 및 늦게 도착한 응답,
  수정 클릭 1회 호출, 읽기 전용 권한, 삭제 수주/배정완료 수주 제어 검증.
  JSON 선택, 기존 LOT 보존, 일부 미확인, 원문 비교, 입력 내용 이스케이프,
  조회 중 DB 쓰기 요청 없음, 원문 행 불변 검증.
- 제공 JSON의 실제 1,863개 LOT 식별값을 사용한 오프라인 대조:
  이전 형식 원문 1,863개 모두 조회 / 일부 1,000개 조회·863개 미확인 /
  DB 조회 결과가 비어 있으면 0개 조회·1,863개 미확인으로 표시함.
- public JavaScript 45개 구문 및 상대 import 경로 검사.
- database/server/netlify/supabase/config.js/netlify.toml 보존 확인.
- ZIP CRC, 압축 덮어쓰기 모의 적용 및 기존 config.js 보존 확인.

범위
- SQL·서버·계정 함수·연차/사원번호 연계·환경설정 변경 없음.
- 운영 Supabase/GitHub/Netlify에 직접 접속, 업로드, 배포하지 않음.
- 실제 브라우저 실행은 이 환경의 프로세스 소켓 제한으로 불가.
  화면 동작은 jsdom의 실제 컨트롤러로 검증했으며 운영 브라우저/통신 결과를 보증하지 않음.
- 수주·LOT·실적 자동 이전 완료본이 아님. 원문 자료의 위치와 DB 등록 여부를 확인하는 보완임.
