DNM MES 4.10.3 수정·검증 결과 / 2026-11-12

수정 근거
- 민수 Routing의 수주 선택목록은 민수 구분/연결 Routing만 검사하고
  수주 CANCELLED 및 data.deleted 상태를 제외하지 않았음.
- 업로드한 부싱 JSON은 source_routing 원문 참조자료이며 업무용 order/routing/operation
  생성 자료가 아니었음. 조회 개선만으로는 작업실적을 입력할 수 없음.

수정 내용
- 삭제된 수주 선택 제외, 삭제된 기존 선택값 초기화, 분할창 진입 전 수주 재조회.
- SQL29: 새 전환/검토 함수, 전환 확인값 보관, 삭제 수주의 Routing 재생성/재활성화 차단.
- 실제 업무 기능으로 검증된 수주·LOT 생성 경로를 사용. 전환된 원본과 운영 LOT 연결 유지.
- 새로 생성한 동일 공정의 민수 LOT에 한해 기본 배포 검증 후 일괄 배포.
  감사/버전 트리거는 유지하고, 기존 운영 Routing은 변경 대상에 포함하지 않음.
- 정상 행 전환, 문제 행 보류와 이유, 명시적 제외/재검토, 동일 요청·동시 요청 중복 방지.
- 신규 자료 전환은 관리자만 가능하며 UI와 DB 양쪽에서 검사.
- 입력 오류·응답 유실 뒤 다시 저장할 때 기존 비활성 입력상태를 유지.
- 공정 설비·작업자 선택 설명, 메뉴별 사용방법, 4.10.3 버전 표시 갱신.

검증 결과
- Node.js 단위/회귀시험 297개 통과.
- 실제 컨트롤러 DOM: 기존 민수 39개, 수주·원문 28개, 신규 전환·삭제 수주·문서 보완 33개 통과.
- PostgreSQL 18.6 독립 시험 DB: 기존 158개 + 민수 73개 + 4.10.1 41개 통과.
- 신규 전환 42개 및 문서항목 보완 8개 통과: 새 수주/기존 수주 연결, 작업지시 배포, 실제 작업일보 등록,
  누락수량/완료자료/잘못된 날짜/S/O 불일치 보류, 정상행만 처리, 전체 실패 롤백,
  수주 초과배정 차단, 원문 불변, 제외/재검토/취소 후 재전환, 권한, 중복/동시 요청.
- 500 원문 LOT × 17공정 = 8,500개 공정 생성 및 배포: 마지막 시험 약 96.9초.
  실행시간은 시험 환경의 측정값이며 운영 Supabase의 속도를 의미하지 않음.
- 기존 분할 경쟁시험 3개 통과. 같은 수주 과다배정·월별 번호 충돌 방지 유지.
- 원본 JSON 1,863건을 독립 DB에 등록·재등록하여 동일 요청/같은 LOT 중복 방지 검증.
- 제공 진단의 연차 17개 테이블·함수 23개와 가상 연결 데이터로 호환시험 16개 통과.
  SQL29 LF/CRLF 반복 적용 시 연차/직원/설정/업무행과 기존 함수/권한/트리거 보존.
  기존 사원번호 연결의 부서 변경 및 미사용 동기화도 확인.
- public JavaScript 47개 구문 검사와 상대 import 파일 경로 확인.
- 기존 database SQL01~28, server, netlify, supabase, config.js, netlify.toml 파일 동일 확인.
- ZIP CRC, 파일 해시 및 기존 저장소에 병합하는 모의 적용 검증.

범위와 한계
- 운영 Supabase/GitHub/Netlify에 직접 접속하거나 변경·전환·배포하지 않음.
- 최신 실 DB 전체와 직접 대조한 결과가 아니라 제공 소스/진단 및 독립 시험 결과임.
- 브라우저 실행이 제한된 환경이므로 jsdom에서 실제 화면 컨트롤러/입력/RPC 연결을 검증함.
  실제 운영 브라우저 화면·네트워크를 직접 검증한 결과가 아님.
- 500 LOT × 17공정 배포를 실측했으며 500 LOT × 60공정 최대 전체 부하는 실측하지 않음.
- 원문에 없는 수량·상태·과거 작업실적은 사용자 확인이 필요함.
- 환경변수나 연결 설정 변경은 필요 없으나 전환 기능 사용에는 SQL29 적용이 필요함.
