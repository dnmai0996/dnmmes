먼저 알아둘 내용

이 파일은 별도 공통관리 웹앱입니다. 품목 식별정보, 거래처, 공유메모, 사용자 권한, 변경 이력을 제공합니다. 기존 MES의 수주엑셀 가져오기, Routing Sheet, 제조·검사 지시, 작업일보, 구매 결재 기능과 기존 DB 자동 이관은 포함하지 않습니다.

현재 파일에는 실제 프로젝트 URL·키·업무자료가 없습니다. 아래 순서로 본인의 Supabase와 Netlify에 적용하면 실제 데이터를 저장하는 앱으로 사용합니다. 계정 생성·배포·실기 검증은 이 파일을 만든 환경에서 수행하지 않았습니다.

새 폴더에 압축을 풀어 사용하세요. 기존 D:\DNM\app에 덮어쓰지 마세요. 예: D:\DNM\CloudAdmin.

① DB② 관리자③ config.js④ GitHub⑤ Netlify⑥ 휴대폰 확인사용자 추가문제 해결

준비물과 완료 기준

GitHub, Netlify, Supabase에 로그인할 수 있는 계정과 관리자 이메일을 준비하세요. 이 앱은 React, Node 서버, npm start, .env, 포트 개방, 사설 IP, 고정 IP가 필요하지 않습니다. 각 서비스의 요금과 사용량 한도는 선택한 계정에서 확인하세요.

구성역할
GitHub소스코드·버전 이력. 실제 업무자료와 DB 비밀번호는 올리지 않습니다.
Netlifypublic 폴더의 HTML/CSS/JS를 HTTPS 주소로 제공합니다.
Supabase이메일 로그인과 PostgreSQL 데이터 저장. 사용자별 DB 접근 권한을 적용합니다.
휴대폰 / PC같은 Netlify 주소로 접속합니다. 사내 인터넷·모바일 데이터 모두 사용 가능합니다. 조직망에서 외부 서비스 접속을 차단하면 해당 네트워크의 허용 설정이 필요합니다.

완료 기준: PC에서 등록한 일반 사무용 품목을 휴대폰에서 확인하고, 휴대폰에서 입력한 공유메모를 PC와 Supabase Table Editor에서 확인합니다.

01

Supabase 프로젝트와 테이블 만들기

  1. Supabase Dashboard에 로그인하고 New project를 선택합니다.
  2. 프로젝트 이름을 정하고 DB 비밀번호를 비밀번호 관리자 등에 별도 보관합니다. 이 DB 비밀번호는 config.js에 넣지 않습니다. 지역·요금제를 확인하고 프로젝트를 생성합니다.
  3. 프로젝트 생성이 끝나면 왼쪽 SQL Editor → New query를 엽니다.
  4. 압축을 푼 폴더의 database/01_schema.sql을 메모장으로 열고 전체 내용을 복사합니다.
  5. SQL Editor에 붙여넣고 Run을 누릅니다. 오류 없이 완료되어야 다음 단계로 갑니다.
  6. Table Editor에서 아래 5개 테이블을 확인합니다.
테이블 이름저장 내용
dnm_portal_profiles계정 역할·활성 상태
dnm_portal_products품번·품명·Project·단위·사용 상태
dnm_portal_partners거래처 코드·명칭·구분·담당자·연락처
dnm_portal_notes공유메모 제목·내용·작성자
dnm_portal_audit변경 시각·작성자·변경 전후 값

SQL에는 RLS(행 단위 접근 제한)와 권한이 포함되어 있습니다. 테이블 생성 부분만 골라 실행하거나 RLS를 끄지 마세요. 새 Supabase 프로젝트에 설치하는 것을 기준으로 작성했습니다.

02

처음 사용할 관리자 계정 만들기

  1. Supabase의 Authentication → Users → Add user → Create new user를 선택합니다. 화면에 따라 버튼 이름은 조금 다를 수 있습니다.
  2. 관리자 이메일과 12자 이상의 비밀번호를 입력합니다. 이메일 소유를 확인한 관리자 계정에 한해 Auto Confirm User를 선택하여 생성합니다. 비밀번호를 문서나 GitHub에 기록하지 마세요.
  3. database/02_first_admin.sql을 메모장으로 엽니다. 아래 한 곳의 관리자이메일입력만 방금 생성한 이메일로 바꿉니다. 작은따옴표는 유지합니다.
    admin_email text := '관리자이메일입력';
  4. 수정한 파일 전체를 새 SQL Editor 쿼리에 붙여넣고 Run을 누릅니다. 오류가 없어야 합니다.
  5. Table Editor의 dnm_portal_profiles에서 해당 이메일의 role=admin, active=true를 확인합니다.
  6. Authentication → Sign In / Providers의 가입 설정에서 Allow new users to sign up을 끄고, 이메일 로그인을 활성화합니다. 사내 계정은 관리자가 Users 화면에서 생성합니다. Anonymous sign-ins도 사용하지 않습니다.

이 별도 앱은 Supabase 이메일 + 비밀번호로 로그인합니다. 기존 dnmuser 아이디, MySQL 계정, 기존 관리자 OTP는 자동 이관되지 않습니다. 이 버전에는 OTP 로그인 UI와 비밀번호 찾기 메일 흐름이 없습니다.

03

config.js에 두 값 붙여넣기

  1. Supabase 프로젝트 위쪽 Connect에서 Project URL과 Publishable key를 찾습니다. 키 목록은 Settings → API Keys에서도 확인할 수 있습니다.
  2. 프로젝트 URL은 https://프로젝트번호.supabase.co 형태입니다. DB 접속 문자열(postgresql://…)이 아닙니다.
  3. 키는 Publishable key를 복사합니다. 일반적으로 sb_publishable_로 시작합니다.
  4. 압축을 푼 폴더의 public/config.js를 메모장으로 엽니다. 각 줄의 큰따옴표 사이에 실제 값을 붙여넣고 저장합니다.
export const SUPABASE_URL = "";
export const SUPABASE_PUBLIC_KEY = "";

위 코드는 빈칸 상태의 원본입니다. export, 변수명, 따옴표, 세미콜론을 지우지 마세요. 저장 후 파일명이 config.js.txt가 되지 않았는지 확인하세요.

브라우저에는 공개용 키만 넣습니다. Secret key, service_role, DB 비밀번호, 관리자 비밀번호는 넣지 마세요. 공개용 키를 아는 사람도 로그인과 DB 권한을 통과해야 자료에 접근하도록 구성했습니다. 이 앱의 연결 설정은 이 파일 하나이며 .env를 만들지 않습니다.

04

GitHub에 소스 올리기

  1. GitHub 새 저장소를 엽니다. 예를 들어 dnm-cloud-admin이라는 이름의 Private 저장소를 생성합니다.
  2. 저장소 화면에서 uploading an existing file 또는 Add file → Upload files를 누릅니다.
  3. 압축을 푼 폴더 안의 내용을 올립니다. 상위 CloudAdmin 폴더 전체를 한 겹 더 넣지 마세요. ZIP 파일 자체만 올리면 배포할 수 없습니다.
  4. 아래 구조로 올라가는지 확인합니다. 특히 netlify.toml과 public이 저장소 첫 화면에 있어야 합니다.
  5. 변경 설명을 v3.0.0-admin.1 initial로 입력하고 Commit changes를 누릅니다.
저장소 첫 화면의 항목용도
public/index.html, config.js, JS/CSS, 설치 안내
database/01_schema.sql, 02_first_admin.sql, 03_check_setup.sql
tests/개발자용 자동 테스트

START_HERE.html / README.txt / VERIFICATION.txt설치 방법·범위·검증 기록

기존 서버 폴더, 실제 업무 Excel, DB 덤프, 인증 파일은 이 저장소에 섞어 올리지 마세요. 수정한 관리자 이메일을 소스에 남기고 싶지 않으면 02_first_admin.sql을 원본의 자리표시자로 되돌린 뒤 올립니다.

05

Netlify에서 실제 주소 만들기

  1. Netlify에 로그인합니다.
  2. Add new project → Import an existing project를 선택합니다. GitHub를 연결하고 방금 만든 저장소를 선택합니다. GitHub 권한 화면이 나오면 필요한 저장소만 허용합니다.
  3. 아래 배포 설정을 확인합니다. netlify.toml을 읽으면 Publish directory가 자동으로 잡힐 수 있습니다.
설정 항목입력값
Branch to deploymain (실제 저장소 기본 브랜치)
Base directory비워둠
Build command비워둠
Publish directorypublic
Functions directory사용하지 않음
Environment variables추가하지 않음
  1. Deploy를 누르고 배포 상태가 Published가 될 때까지 확인합니다.
  2. 프로젝트에 표시된 실제 HTTPS 주소를 누릅니다. 보통 Netlify가 정한 이름의 https://… .netlify.app 주소입니다. 안내서의 예시 문자열을 주소창에 입력하지 말고, Netlify에서 생성된 주소를 복사하세요.
  3. 로그인 화면이 열리면 02단계의 관리자 이메일과 비밀번호로 로그인합니다.
  4. 같은 주소를 휴대폰 브라우저로 열어 로그인합니다. 127.0.0.1, localhost, 192.168.0.100은 이 앱의 접속 주소가 아닙니다.

첫 화면이 “연결 설정 필요”라면 public/config.js의 빈칸 또는 키 형식을 확인하고 GitHub에 다시 반영하세요. 이후 GitHub의 main 브랜치에 변경을 올리면 Netlify가 새 버전을 배포합니다.

이 버전은 이메일 링크 리다이렉트를 사용하지 않는 비밀번호 로그인입니다. 향후 비밀번호 찾기·메일 로그인 기능을 구현할 때 Supabase의 Site URL과 Redirect URLs도 실제 Netlify 주소에 맞춰 설정해야 합니다.

06

PC·휴대폰의 실제 저장 확인

  1. PC에서 실제 Netlify 주소에 로그인합니다. 품목 기준정보 → 신규 등록을 누릅니다.
  2. 품번 OFFICE-001, 품명 사무용 보관함, Project 사무관리, 단위 EA를 입력하고 저장합니다. “저장했습니다”가 보여야 합니다.
  3. 휴대폰에서 같은 주소와 계정으로 로그인한 뒤 품목 기준정보의 새로고침을 누릅니다. 같은 자료가 보여야 합니다.
  4. 휴대폰의 공유메모 → 신규 등록에서 제목과 내용을 입력해 저장합니다. PC의 공유메모를 새로고침하여 확인합니다.
  5. Supabase Table Editor → dnm_portal_notes에도 같은 내용이 있는지 확인합니다. 이것으로 브라우저에만 저장된 자료가 아님을 확인합니다.
  6. 휴대폰 Wi-Fi를 끄고 모바일 데이터로 같은 주소를 열어 조회합니다. 내부 앱 서버를 꺼도 외부 인터넷과 Supabase가 정상이라면 이 앱은 계속 사용할 수 있습니다.
  7. 화면을 켜 둔 상태에서는 약 30초 간격으로 현재 목록을 다시 조회합니다. 입력 중·팝업이 열린 동안·백그라운드에서는 자동 조회를 쉬므로 새로고침을 누르면 바로 확인할 수 있습니다.

인터넷이 끊어지면 공동 DB 조회·저장을 할 수 없습니다. 오프라인 저장이나 나중에 자동 합치는 기능은 제공하지 않습니다. 응답을 못 받은 저장은 목록을 확인하기 전 다시 전송하지 않도록 안내합니다.

직원 계정과 권한 관리

  1. Supabase Authentication → Users에서 직원의 이메일 계정을 생성합니다. 비밀번호는 안전한 개인 전달 경로로 안내합니다.
  2. 포털 관리자 계정으로 로그인하고 사용자 관리에서 해당 직원을 찾습니다.
  3. 권한 변경을 눌러 성명·역할을 정하고 사용 허용을 체크한 뒤 저장합니다.
  4. 직원이 포털에 로그인합니다. 권한을 변경한 사용자는 로그아웃 후 재로그인하면 메뉴도 갱신됩니다.
역할허용 범위
관리자전체 자료 조회·수정, 다른 사용자 활성화·역할 변경, 변경 이력 조회
담당자품목·거래처 등록·수정, 공유메모 작성, 본인 메모 수정
조회자품목·거래처·공유메모 조회
대기/차단업무 데이터 접근 불가. 새 계정의 초기 상태

이 버전은 같은 회사 구성원들이 공통 자료를 보는 구조이며 회사별 분리 기능은 없습니다. 사용자는 자신의 역할을 직접 올릴 수 없습니다. 앱에서는 영구 삭제 대신 품목·거래처의 “사용 중” 체크를 해제합니다. 공유메모 삭제 UI는 없습니다.

비밀번호를 알고 있는 사용자는 오른쪽 위 비밀번호에서 현재 비밀번호를 확인한 후 변경할 수 있습니다. 분실 복구·OTP 기능은 이 버전에 없으므로 자체 계정 복구 절차를 정한 후 사용자를 늘리세요. 기존 계정을 삭제·재생성하면 사용자 ID와 메모 소유 관계가 달라지므로 임의로 삭제하지 마세요.

공용 PC에서는 사용 후 로그아웃하세요. 로그인 세션은 탭의 sessionStorage에 보관하며 업무자료·비밀번호를 브라우저 저장소에 저장하지 않습니다.

휴대폰 음성 입력과 Ollama

  1. 공유메모 등록 창에서 제목을 적고 음성 입력을 누릅니다.
  2. 브라우저가 마이크 사용을 물으면 이 사이트에 허용합니다. Netlify의 HTTPS 주소에서 사용하세요.
  3. 한국어로 말한 뒤 인식된 문장을 확인·수정하고 저장을 누릅니다. 음성 인식만으로 DB에 자동 저장하지 않습니다.
  4. 미지원 브라우저에서는 앱 음성 버튼이 비활성화됩니다. 내용 칸에 직접 입력하거나 휴대폰 키보드의 받아쓰기를 사용합니다.

브라우저 음성 인식 지원은 기기와 버전에 따라 다르고, 음성이 브라우저 제공자의 외부 인식 서비스에서 처리될 수 있습니다. 이 앱이 내부 서버나 Ollama로 음성을 보내는 기능은 없습니다.

Ollama는 미연결 상태로 제공합니다. 관련 서버·주소·키 설정 없이 모든 포함 기능이 동작합니다. 추후 연결은 별도 개발 범위이며 내부 Ollama 포트를 인터넷에 개방하는 절차는 이 배포에 포함되지 않습니다.

DB 설정 확인과 버전 업데이트

01·02단계가 끝난 후 database/03_check_setup.sql을 SQL Editor에서 실행하면 테이블·RLS·초기 관리자 상태를 확인할 수 있습니다. 이 검사는 접속·휴대폰·사용자별 실제 권한 검증을 대신하지 않습니다.

  1. 현재 소스를 GitHub에 Commit하고 버전 v3.0.0-admin.1 태그나 Release로 표시하면 복원할 지점을 알 수 있습니다.
  2. 업데이트 파일을 반영할 때 본인의 public/config.js 두 값은 유지합니다.
  3. 화면 수정은 GitHub에 Commit → Netlify Published 확인 → PC·휴대폰 새로고침 순서로 적용합니다.
  4. 향후 DB 변경은 별도 번호의 SQL 마이그레이션과 백업을 확인한 후 적용해야 합니다. GitHub 코드 복원은 DB 데이터를 되돌리지 않습니다.

현재 01_schema.sql은 데이터 삭제 없이 동일 설치를 다시 적용할 수 있도록 작성했지만, 향후 다른 버전의 DB를 이 파일로 되돌리는 용도는 아닙니다.
