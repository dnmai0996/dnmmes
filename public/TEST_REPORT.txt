DNM MES 4.10.1 변경·검증 결과 / 2026-11-12

반영한 기능
- 민수 LOT 일괄 생성 최대 500개, LOT당 60개 공정(전체 최대 30,000개).
- 민수 수주 수정·삭제, 수주수량/LOT 배정합계/미배정 잔량 표시, 잔량 추가 LOT 작성.
- 다른 LOT의 진행·완료 여부와 관계없이 유효 실적 0인 민수 LOT 삭제.
  진행·수량 확인대기는 먼저 종료·확정. 생산·검사 실적 있는 LOT는 삭제 불가.
- 삭제는 현재 목록 제외와 상태 변경이며 기존 행·번호·이력을 보존.
- 작업일보 수량·시간·작업내용·비고 정정, 이전 값·수정 사유 보관, 공정 누적 재계산.
- 마지막 공정 종료 후 일반 사용자 수정 차단, 시스템 관리자 정정 허용.
  관리자 정정으로 최종공정이 다시 열려도 일반 사용자 수정 잠금 유지.
- 확정 검사수량보다 줄이는 변경과 LOT 미연결 최종검사·출하 기록의 수량 축소 차단.
- 비고 신규 입력, 목록·인쇄·CSV 표시. 민수 실제 작업자·설비 정정 시 기존 권한 검증.
- 부싱 원문 확인대기 목록/등록 연결, 같은 원본 LOT 중복 방지. 기존 원문 보존.

시험 결과
- 기존 Node.js 자동검증 267개 통과.
- 실제 화면 컨트롤러 DOM 검증 39개 통과.
- PostgreSQL 18.6: 기존 158개, 4.10.0 민수 73개, 이번 추가 41개 통과.
- 500 LOT × 17공정 = 8,500 작업지시 생성·재시도 검증.
  마지막 독립 시험 실행시간 약 23초. 실제 Supabase 처리시간은 서버·자료량에 따라 다름.
- 다중 접속 경쟁 3개 통과: 동일 요청 중복 방지, 수주 초과배정 차단, 월 순번 충돌 방지.
- SQL28 LF/CRLF 실행과 교차 재실행, 기존 업무행 보존 확인.
- 진단에서 확보한 연차 17개 테이블·함수 23개를 시험용 DB에 구성해 17개 호환검증 통과.
  연차 이력/잔액/직원번호/MES UUID/이전 사원번호/설정/권한/관련 함수·트리거 보존.
  부서 변경·미사용 직원 동기화 성공, 실제 함수 불일치 시 전체 변경 롤백 검증.
- 첨부 원문 1,863건을 100건씩 19회 등록. 동일 요청 재시도·다른 코드 동일 LOT 중복 방지.
  업무 수주·Routing·작업일보·구매 등 비원문 자료는 변경되지 않음을 해시로 확인.
- JavaScript 42개 구문 및 상대 import 경로 확인.
- 현재 config.js, Netlify/Supabase 설정, 서버·계정 함수 파일 원본 동일 확인.
- 업데이트 압축 덮어쓰기 모의 검증과 ZIP CRC 검증. 3쪽 사용안내 PDF 렌더 검토.

검증의 한계와 운영 상태
- 사용자 운영 Supabase, GitHub, Netlify에 직접 접속하거나 변경한 작업은 없음.
- 운영 DB 전체 최신 실데이터 백업과 직접 대조한 결과가 아님.
- 연차 연계 검증은 제공 진단의 함수·구조와 시험용 연결 데이터를 사용함.
- 실제 브라우저(Chromium) 실행이 제한된 환경으로 UI 입력·RPC 연결은 DOM에서 검증함.
- 최대 500 LOT는 17공정 사례로 검증. 500 LOT × 60공정 전체 최대 부하는 별도 실측하지 않음.
- 이번 자료는 작업지시/실적 자동 이전 완료본이 아니라 원문 확인대기 등록 자료임.
  현재 진행상태와 LOT 수량·연결할 수주·S/O·Heat Code 확인 후 운영 지시로 이전 필요.
