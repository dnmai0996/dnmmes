로그인 통신 오류를
정확히 확인하는 수정본

로그인 오류에 자료 저장용 안내가 표시되던 문제를 고쳤습니다. 새 연결 진단으로 실제 Project URL과 인증 서비스 응답을 확인할 수 있습니다. 이 패치 자체가 외부 접속 장애의 해결 완료를 의미하지는 않습니다.

1. GitHub에서 파일 3개 교체

  1. 배포에 연결한 GitHub 저장소의 public 폴더를 엽니다.
  2. Add file → Upload files를 누릅니다.
  3. 이 압축의 public 폴더 안에서 api.js, app.js, core.js 세 파일을 선택해 끌어 넣습니다.
  4. 변경 경로가 public/api.js, public/app.js, public/core.js인지 확인합니다. public/public/이 되면 안 됩니다.
  5. Commit changes를 누릅니다. 배포 브랜치(main)에 적용되어야 합니다.

기존 config.js를 그대로 유지하세요. 이 패치에는 설정 파일이 없습니다. Supabase SQL과 테이블을 다시 만들 필요도 없습니다.

2. 배포 확인

  1. Netlify의 Deploys에서 새 배포가 Published로 완료되는지 확인합니다.
  2. https://dnmmes.netlify.app을 열고 Ctrl+F5를 누릅니다.
  3. 로그인 화면의 버전이 3.0.1-admin.1인지 확인합니다.

3. 비밀번호 없이 연결 진단

  1. 로그인 버튼 아래의 Supabase 연결 진단을 펼칩니다.
  2. 화면에 표시된 연결 주소를 Supabase 프로젝트의 실제 Project URL과 대조합니다. URL 형식이 맞아도 다른 프로젝트 주소이거나 오타이면 접속되지 않을 수 있습니다.
  3. 연결 확인 (비밀번호 불필요)를 누릅니다. 인증 서비스의 공개 설정만 조회합니다.
  4. 아래 표에 따라 결과를 확인합니다. 진단 성공 뒤 실제 로그인으로 계정·업무 DB 접근을 확인하세요.
결과다음 확인
공개 설정 정상 조회인증 서비스와 공개용 키 요청이 응답했습니다. 이메일 로그인 → 사용자 활성 상태 → 업무 DB 조회 순서로 확인합니다.
HTTP 401config.js의 Project URL과 Publishable key가 같은 Supabase 프로젝트의 값인지 확인합니다.
HTTP 404실제 프로젝트 주소와 인증 서비스 경로를 확인합니다.
HTTP 429요청을 잠시 멈춘 후 다시 시도합니다.
HTTP 5xxSupabase 프로젝트와 인증 서비스의 실행 상태를 확인합니다.
이메일 로그인 꺼짐Supabase Authentication → Sign In / Providers에서 Email 설정을 확인합니다.
CONNECTION_FAILED / TIMEOUT주소 오타, DNS, 브라우저 차단, 통신 오류 등을 이 결과만으로 구분할 수 없습니다. 실제 Project URL과 프로젝트 실행 상태를 먼저 확인합니다. 휴대폰 Wi-Fi를 끄고 모바일 데이터로 동일한 Netlify 주소에서 진단해 비교합니다.
INVALID_RESPONSE정상적인 인증 서비스 응답 형식이 아닙니다. 연결 주소와 프록시/차단 화면 여부를 확인합니다.

다음 결과를 공유할 때

연결 진단을 펼친 결과 화면을 공유하면 다음 단계를 판단할 수 있습니다. 이 화면에는 공개 프로젝트 URL과 결과가 표시되며 키 전체·비밀번호·로그인 토큰은 표시되지 않습니다.

검증 범위

자동 테스트 24개 통과, JavaScript 구문 검사 통과. 모의 HTTP 응답을 이용해 로그인 오류/저장 오류 분리, 연결 진단, 공개용 키 거절, 응답 형식 오류, 시간 초과, 기존 저장 충돌과 인증 동작을 확인했습니다. 실제 Supabase·Netlify·PC·휴대폰에서의 로그인 검증은 아직 수행하지 않았습니다.
